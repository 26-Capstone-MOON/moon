# 경로 이탈 감지 및 재라우팅 알고리즘 문서

**MOON 프로젝트** — 랜드마크 기반 공간 기술 보행자 네비게이션 시스템

---

## 1. 개요

### 1.1 목적

GPS 기반 보행자 네비게이션에서 두 가지 문제를 해결한다:

1. **GPS 일시적 좌표 튐**과 **실제 경로 이탈**을 구분한다.
2. 실제 이탈이 확인된 경우에만 재라우팅을 수행한다.

도심에서 GPS는 5~10m의 오차가 흔하고, 고층 건물 사이에서는 순간적으로 수십 미터가 튀기도 한다. 이런 일시적 오류에 매번 "경로를 벗어났습니다"라고 안내하면 사용자 신뢰가 무너진다. 반대로 실제 이탈을 놓치면 사용자는 잘못된 방향으로 계속 걷게 된다. 이 알고리즘은 그 균형을 잡는다.

### 1.2 시스템 내 위치

경로 이탈 감지는 **길 안내 파이프라인(STEP 1~6) 이후**, 실시간 네비게이션 루프에서 동작한다.

```
[길 안내 파이프라인 — 경로 생성 시 1회 실행]
  STEP 1~6 → 경로 + DP + 랜드마크 + 안내문 생성
                ↓
[실시간 네비게이션 루프 — 매 1초 반복]
  클라이언트 GPS 전송 (WebSocket)
        ↓
  경로 이탈 감지 모듈 ← 이 문서의 범위
        ↓
  결과에 따라: 정상 안내 계속 / 경고 / 재라우팅
```

이 모듈은 **순수 연산**만 수행한다. 외부 API를 호출하지 않고, 입력(GPS 좌표)과 경로 LineString만으로 판정한다. 재라우팅이 필요하다고 판단하면 그 신호를 보낼 뿐, 실제 Tmap 재호출이나 파이프라인 재수행은 별도 서비스가 담당한다.

### 1.3 전체 흐름 요약

```
매 GPS 업데이트 (1초 간격)
        ↓
  [1] 속도 필터링
      순간 속도 > 15km/h → GPS 오류 → 좌표 폐기
        ↓
  [2] 경로까지 최단 거리 계산
      ≤ 20m → 정상 → 타이머 리셋
      > 20m → 이탈 의심
        ↓
  [3] 지속 시간 확인
      < 3초 → 일시적 → 무시
      ≥ 3초 → 경고 ("경로를 벗어난 것 같아요")
      ≥ 5초 → 연속성 확인으로 진행
        ↓
  [4] 연속성 확인
      거리 증가 추세 → 이탈 확정 → 재라우팅
      거리 감소 추세 → 복귀 중 → 대기
      불규칙 → 판단 보류 → 모니터링 계속
```

## 2. 사전 지식

### 2.1 경로 LineString

Tmap 보행자 API 응답에 포함된 LineString은 경로를 표현하는 **좌표 배열**이다. 연속된 두 좌표를 잇는 선분(segment)들의 집합으로, 도로의 커브와 꺾임을 반영한다.

```
좌표 4개 → 선분 3개:

  A ───── B ───── C ───── D
  선분1     선분2     선분3
```

경로 이탈 감지의 핵심 질문은 "사용자의 현재 GPS 좌표가 이 LineString으로부터 얼마나 떨어져 있는가?"이다.

### 2.2 점-선분 최단거리 (Point-to-Segment Distance)

#### 왜 필요한가

"사용자가 경로에서 얼마나 벗어났는가?"를 판단하려면 GPS 좌표에서 경로까지의 거리를 알아야 한다. 경로는 선분들의 집합이므로, 가장 기본이 되는 연산은 **점 하나와 선분 하나 사이의 최단거리**이다.

단순히 "GPS 좌표와 경로 위 꼭짓점(A, B) 사이의 거리"만 구하면 안 된다. 사용자가 선분의 **중간 지점** 옆에 있을 때, 양 끝점까지의 거리는 멀지만 선분까지의 실제 거리는 가까울 수 있기 때문이다.

```
         P (사용자)
         ↓  ← 이 수직 거리가 진짜 거리
  A ─────┼──────── B
         C (최근접점)
```

이 거리를 구하기 위해 세 단계가 필요하다.

#### ① 사영 (Projection) — "선분 위 어디가 가장 가까운가?"

점 P에서 선분 AB 위에 수선을 내려, 수선의 발이 선분 위 어디에 위치하는지를 구한다.

**도출 과정**: 벡터 AP(A에서 P로 가는 방향)를 벡터 AB(A에서 B로 가는 방향, 즉 선분 방향)에 정사영(orthogonal projection)한다. 정사영의 정의에 따라 사영 길이는 두 벡터의 내적을 선분 길이의 제곱으로 나눈 값이다:

> t = (AP · AB) / |AB|^2

t는 선분 위의 **비율**을 나타낸다:
- t = 0: 수선의 발이 A 위치 (P가 A 쪽에 가장 가까움)
- t = 1: 수선의 발이 B 위치 (P가 B 쪽에 가장 가까움)
- 0 < t < 1: 수선의 발이 선분 중간 (P의 수선이 선분 위에 떨어짐)

t가 0보다 작거나 1보다 크면 수선의 발이 선분 바깥에 떨어지는 것이므로, [0, 1] 범위로 **클램핑(clamping)**한다. 이렇게 하면 선분의 연장선이 아닌 선분 자체 위에서 가장 가까운 점을 찾는 것이 보장된다.

**사용 목적**: 이 t 값이 없으면 "GPS에서 선분까지의 거리"를 구할 수 없다. 선분의 양 끝점(A, B)만으로는 선분 중간 지점과의 거리를 알 방법이 없기 때문이다.

**예시**: 선분 A = (0, 0), B = (10, 0), 점 P = (7, 3)인 경우:

> AP = (7, 3),  AB = (10, 0)
> t = ((7 x 10) + (3 x 0)) / (10^2 + 0^2) = 70 / 100 = 0.7

t = 0.7이므로, 수선의 발은 A에서 선분의 70% 지점에 있다. 만약 P = (-3, 5)였다면 t = -0.3이 나오는데, 이때 0으로 클램핑하여 A 자체가 최근접점이 된다.

#### ② 최근접점 계산 — "선분 위 그 지점의 좌표는?"

t를 구했으면 선분 위의 최근접점 C의 좌표를 구한다:

> C = A + t x (B - A)

이것은 A와 B 사이의 **선형 보간(linear interpolation)**이다. t = 0이면 C = A, t = 0.5이면 C는 중점, t = 1이면 C = B가 된다.

**사용 목적**: 최종 거리를 계산하려면 "GPS 좌표 P"와 비교할 "경로 위 좌표 C"가 있어야 한다. ①에서 구한 비율 t를 실제 좌표로 변환하는 단계이다.

**예시** (위의 t = 0.7 계속):

> C = (0, 0) + 0.7 x ((10, 0) - (0, 0)) = (0, 0) + (7, 0) = (7, 0)

최근접점은 (7, 0)이다. 직관적으로도, P = (7, 3)에서 x축 위의 선분에 수선을 내리면 (7, 0)에 닿는 것이 맞다.

#### ③ 거리 계산 — "GPS에서 최근접점까지 실제로 몇 미터인가?"

점 P와 최근접점 C 사이의 거리를 **Haversine 공식**으로 구한다.

**왜 Haversine인가**: 위도·경도는 구면 좌표(spherical coordinates)이다. 평면에서의 유클리드 거리(sqrt((x2-x1)^2 + (y2-y1)^2))를 쓰면 지구 곡률이 반영되지 않아 오차가 생긴다. 특히 위도 1°와 경도 1°의 실제 거리가 다르기 때문에(위도 1° ≈ 111km이지만, 경도 1°는 위도에 따라 변함) 단순 좌표 차이로는 정확한 미터 거리를 얻을 수 없다.

**하이브리드 접근**: ①의 사영 계수 t를 구할 때는 근사적으로 평면 좌표를 사용한다. 20m 스케일에서 지구 곡률의 영향은 무시할 수 있기 때문이다(20m에서 구면-평면 오차 < 0.01m). 하지만 최종 거리는 정확성을 위해 Haversine으로 계산한다.

**예시** (위의 계속): P = (7, 3), C = (7, 0)이므로 평면에서는 거리가 3이다. 실제 좌표라면 P = (37.49860, 127.02830), C = (37.49860, 127.02800)과 같은 식이 되고, Haversine으로 계산하면 약 25m가 나온다. 이 값이 20m를 초과하므로 이탈 의심이 된다.

**사용 목적**: 이 거리값이 20m 이하인지 초과인지가 곧 "정상 vs 이탈 의심"의 판정 기준이 된다(5장 참조).

### 2.3 점-LineString 최단거리

#### 왜 필요한가

2.2절의 점-선분 거리는 **선분 하나**에 대한 것이다. 하지만 실제 경로는 선분이 수십~수백 개로 이루어진 LineString이다. 사용자가 경로의 어느 부분 근처에 있든 정확한 거리를 구하려면, **모든 선분에 대해** 거리를 계산하고 최솟값을 취해야 한다.

> d_min = min(point_to_segment(P, S1), point_to_segment(P, S2), ..., point_to_segment(P, Sn))

여기서 Si는 LineString의 i번째 선분, n은 전체 선분 수이다.

#### 왜 최솟값인가

경로가 꺾이거나 곡선을 그리면, GPS 좌표에서 가장 가까운 선분이 **반드시 첫 번째 선분이나 마지막 선분이 아니다**. L자 형태의 경로를 생각해보면:

```
  A ──── B
         │
    P ·  │   ← P는 두 번째 선분(B→C)에 가장 가까움
         │
         C
```

첫 번째 선분(A→B)까지의 거리는 멀지만, 두 번째 선분(B→C)까지의 거리는 가깝다. 모든 선분을 검사하지 않으면 이런 경우를 놓친다.

**예시**: 경로가 3개 선분 S1, S2, S3으로 이루어져 있고, GPS 좌표 P에 대해 각 선분까지의 거리가 다음과 같다면:

| 선분 | 거리 |
|---|---|
| S1 (A→B) | 45m |
| S2 (B→C) | 8m |
| S3 (C→D) | 62m |

> d_min = min(45, 8, 62) = 8m

8m ≤ 20m이므로 **정상** 판정. 만약 S1만 검사했다면 45m > 20m으로 거짓 이탈이 발생했을 것이다.

#### 어디에 사용하는가

이 d_min 값이 경로 이탈 감지의 **핵심 입력**이다. 매 1초마다 GPS가 들어올 때마다 이 값을 계산하여:
- 20m 이하 → 정상 (NORMAL)
- 20m 초과 → 이탈 의심 (SUSPECTED)

으로 판정한다. 또한 연속성 확인(7장)에서도 시간순 3개 GPS 각각에 대해 이 값을 계산하여 추세(멀어지는지/돌아오는지)를 판단한다.

### 2.4 순간 속도 계산

#### 왜 필요한가

GPS 신호가 순간적으로 튀면 1초 만에 수십~수백 미터가 이동한 것으로 찍힌다. 이 좌표를 그대로 이탈 감지에 쓰면, "정상 보행 중인데 갑자기 500m 바깥으로 이탈"이라는 거짓 판정이 발생한다. 이를 사전에 걸러내기 위해 **연속 두 GPS 사이의 순간 속도**를 계산하고, 보행자가 물리적으로 낼 수 없는 속도이면 GPS 오류로 판정한다.

#### 공식 도출 과정

속도의 기본 정의는 v = d / t (거리 ÷ 시간)이다.

**거리 d**: 이전 GPS 좌표 P1과 현재 GPS 좌표 P2 사이의 실거리를 Haversine 공식으로 구한다. 단위는 미터(m)이다.

> d (m) = haversine(P1, P2)

**시간 dt**: 두 GPS의 타임스탬프 차이. 단위는 초(s)이다.

> dt (s) = t2 - t1

**속도 변환**: d / dt의 단위는 m/s이다. 보행 속도는 보통 km/h로 표현하므로 변환한다. 1 m/s = 3.6 km/h이므로:

> v (km/h) = (d / dt) x 3.6

3.6이라는 변환 계수는 단위 분석에서 나온다: (m/s) x (3600s / 1h) x (1km / 1000m) = (m/s) x 3.6

최종 공식:

> v (km/h) = haversine(P1, P2) / (t2 - t1) x 3.6

**예시 1 — 정상 보행**: 1초 전 GPS (37.49800, 127.02800), 현재 GPS (37.49801, 127.02801). Haversine 거리 ≈ 1.3m.

> v = (1.3 / 1) x 3.6 = 4.7 km/h → 15km/h 이하, 정상

**예시 2 — GPS 튐**: 1초 전 GPS (37.49800, 127.02800), 현재 GPS (37.50300, 127.03200). Haversine 거리 ≈ 555m.

> v = (555 / 1) x 3.6 = 1,998 km/h → 15km/h 초과, GPS 오류 → 폐기

#### 어디에 사용하는가

이 속도값이 **15km/h를 초과하면 GPS 오류로 판정**하고 해당 좌표를 완전히 폐기한다(4장 참조). 이탈 감지 파이프라인의 가장 첫 번째 필터로, 오류 좌표가 이후 단계(거리 판정, 지속 시간, 연속성 확인)에 영향을 주지 않도록 차단하는 역할이다.

## 3. 상태 머신 (State Machine)

경로 이탈 감지는 **상태 기반**으로 동작한다. 매 GPS 입력마다 현재 상태와 조건에 따라 다음 상태로 전이한다. 이 설계의 핵심은 "한 번의 GPS 값으로 즉시 판단하지 않고, 시간에 걸쳐 누적된 증거로 판단한다"는 것이다.

### 3.1 상태 정의

| 상태 | 의미 | 사용자 안내 |
|---|---|---|
| **NORMAL** | 경로 위에 있음 | (안내 없음, 정상 네비게이션) |
| **SUSPECTED** | 이탈 의심 (20m 초과, 3초 미만) | (안내 없음, 내부 감시) |
| **WARNING** | 경고 (20m 초과, 3초 이상) | "경로를 벗어난 것 같아요" |
| **CONFIRMING** | 추세 불분명 (5초 이상, 비단조) | (안내 없음, 모니터링 계속) |
| **DEVIATED** | 이탈 확정 (거리 증가 추세) | "경로를 다시 찾고 있어요" |
| **RETURNING** | 복귀 중 (거리 감소 추세) | "다시 돌아오고 있어요" |

### 3.2 상태 전이 다이어그램

```
                         dist ≤ 20m (어느 상태에서든)
              ┌──────────────────────────────────────────┐
              ↓                                          │
          [NORMAL]                                       │
              │                                          │
              │ dist > 20m (최초)                        │
              ↓                                          │
         [SUSPECTED]  ──── dist ≤ 20m ──→ [NORMAL]      │
              │                                          │
              │ 지속 ≥ 3초                               │
              ↓                                          │
          [WARNING]  ──── dist ≤ 20m ──→ [NORMAL]       │
              │                                          │
              │ 지속 ≥ 5초 + 추세 분석                    │
              ├─── 거리 증가 (d1<d2<d3) ──→ [DEVIATED]  │
              ├─── 거리 감소 (d1>d2>d3) ──→ [RETURNING] ─┘
              └─── 불규칙 ─────────────→ [CONFIRMING] ──┘
```

**핵심 원칙**: 어떤 상태에 있든 경로까지 거리가 20m 이내로 돌아오면 즉시 NORMAL로 리셋된다. 모든 내부 타이머와 거리 기록이 초기화된다.

## 4. 속도 필터링

### 4.1 문제

GPS 신호가 튀면 1초 만에 수십~수백 미터를 이동한 것으로 찍힌다. 이런 데이터가 이탈 감지 파이프라인에 들어가면 거짓 이탈이 발생한다.

### 4.2 해결

이전 GPS와 현재 GPS 사이의 순간 속도를 계산하여, **15km/h를 초과하면 GPS 오류로 판정**하고 해당 좌표를 완전히 폐기한다.

### 4.3 15km/h 기준의 도출

이 시스템은 **보행자 전용** 네비게이션이다. 따라서 임계값은 "사람이 두 발로 낼 수 있는 최대 속도"를 기준으로 정한다.

| 이동 유형 | 대표 속도 | 비고 |
|---|---|---|
| 일반 보행 | 4~5 km/h | 성인 평균 보행 속도 |
| 빠른 걸음 | 6~7 km/h | 신호 바뀌기 전에 건너는 상황 등 |
| 조깅 | 8~10 km/h | 가볍게 뛰는 속도 |
| 전력 질주 | 12~15 km/h | 일반인이 짧은 거리에서 낼 수 있는 최대 속도 |
| **임계값** | **15 km/h** | |
| GPS 튐 (예시) | 500~2,000+ km/h | 1초에 수백 m 점프 |

15km/h는 **일반인 전력 질주의 상한**이다. 이보다 빠르면 보행자가 물리적으로 낼 수 없는 속도이므로 GPS 오류가 확실하다. 동시에 "갑자기 뛰어야 하는 상황"(횡단보도 신호, 비를 피하는 등)도 15km/h 이내에 들어오므로 정상 이동을 오탐하지 않는다.

만약 이 값을 **12km/h로 낮추면**: 잠깐 뛰는 상황이 GPS 오류로 오탐될 수 있다. **20km/h로 높이면**: GPS가 1초에 5.5m(= 20km/h x 1s / 3.6) 튀어도 통과시키게 되어, 실제 GPS 오류를 걸러내지 못하는 범위가 넓어진다.

### 4.4 설계 포인트

속도 필터링은 **파괴적(destructive)**이다. 오류로 판정된 좌표는 이탈 감지 로직에 전혀 전달되지 않는다. 중요한 것은 **상태가 보존**된다는 점이다. 예를 들어 SUSPECTED 상태에서 GPS가 튀어도 NORMAL로 리셋되지 않고, SUSPECTED를 유지한 채 다음 정상 좌표를 기다린다.

## 5. 경로 이탈 거리 판정

### 5.1 계산

매 GPS 업데이트마다 현재 좌표에서 경로 LineString까지의 최단 거리를 구한다 (2.3절 참조).

### 5.2 판정

| 최단 거리 | 판정 | 동작 |
|---|---|---|
| ≤ 20m | 정상 | NORMAL로 전이, 타이머·거리 기록 리셋 |
| > 20m | 이탈 의심 | SUSPECTED 진입, 타이머 시작 |

### 5.3 임계값 20m의 근거

도심 GPS 정확도가 5~10m이므로, 실제 위치와 GPS 좌표 사이에 항상 오차가 존재한다.

- **10m로 잡으면**: GPS 오차만으로도 이탈 판정이 빈번히 발생 (오탐)
- **30m로 잡으면**: 실제로 옆 골목에 진입했는데도 감지를 못 함 (미탐)
- **20m**: GPS 오차(~10m)를 흡수하면서 실제 이탈(옆 골목 진입)을 감지할 수 있는 균형점

보도 폭(1.5~2m), 건물 후퇴선, 가로수대까지 포함하면 경로 중심선으로부터 10m 이내는 "정상 보행 범위"에 해당한다. 20m는 이 범위에 GPS 오차 마진을 더한 값이다.

## 6. 지속 시간 판정

### 6.1 문제

거리만으로는 GPS 일시 튐과 실제 이탈을 구분할 수 없다. 둘 다 "20m 초과"라는 동일한 거리값을 보이기 때문이다. **차이는 지속 시간에 있다**: GPS 오류는 1~2초 만에 돌아오고, 실제 이탈은 계속 유지된다.

### 6.2 판정 기준

| 이탈 의심 지속 시간 | 판정 | 동작 |
|---|---|---|
| < 3초 | 일시적 (SUSPECTED 유지) | 무시, 다음 GPS 대기 |
| ≥ 3초 | 지속적 (WARNING 전이) | "경로를 벗어난 것 같아요" 안내 |
| ≥ 5초 | 의도적 이동 가능성 | 연속성 확인(7장)으로 진행 |

### 6.3 3초와 5초의 근거

**3초**: GPS 오류의 전형적 패턴은 "1~2초 튀었다가 돌아옴"이다. 3초 이상 지속되면 일시적 현상이라고 보기 어렵다.

**5초**: 보행 속도 4~5km/h에서 5초면 약 6~7m를 이동한다. 이 정도 거리를 경로에서 벗어난 방향으로 걸었다면 의도적 이동(잘못된 방향으로 걸음)일 가능성이 높다. 이 시점에서 추세(멀어지는지 돌아오는지)를 확인한다.

### 6.4 경고 1회 발화 원칙

WARNING 상태 진입 시 "경로를 벗어난 것 같아요"는 **1회만 발화**한다. 3초, 4초, 5초마다 반복하면 오디오 스팸이 된다. 한 번 경고한 후에는 상태 전이(DEVIATED, RETURNING, 또는 NORMAL 복귀)가 있을 때만 새로운 안내를 한다.

## 7. 연속성 확인 (Trend Analysis)

### 7.1 문제

5초 이상 이탈 의심이 지속되더라도 바로 재라우팅하면 안 된다. 사용자가 이미 돌아오는 중일 수 있기 때문이다. 이 시점에서 돌아오는 사용자에게 "새 경로를 찾았습니다"라고 안내하면 혼란만 가중된다.

### 7.2 방법

시간순으로 측정한 **최근 3개 GPS**에서 각각 경로까지 최단 거리를 계산하여 **추세(trend)**를 판단한다.

| d1 (2초 전) | d2 (1초 전) | d3 (현재) | 추세 | 판정 |
|---|---|---|---|---|
| 25m | 30m | 35m | 단조 증가 (멀어지는 중) | **DEVIATED** → 재라우팅 |
| 35m | 30m | 25m | 단조 감소 (돌아오는 중) | **RETURNING** → 대기 |
| 25m | 32m | 28m | 비단조 (불규칙) | **CONFIRMING** → 모니터링 계속 |

### 7.3 단조성(Monotonicity) 판정

3개 연속 거리값의 단조성을 확인한다:

> d1 < d2 < d3  →  DIVERGING (멀어지는 중)
> d1 > d2 > d3  →  CONVERGING (돌아오는 중)
> 그 외  →  IRREGULAR (불규칙)

**3개 샘플을 사용하는 이유**: 2개로는 "증가인지 감소인지"만 알 수 있고 추세의 지속성을 확인할 수 없다. 4개 이상은 판정이 너무 느려져 실시간성이 떨어진다. 3개가 "추세 확인 + 빠른 판정"의 균형점이다.

### 7.4 각 추세별 후속 동작

**DIVERGING → DEVIATED (이탈 확정)**:
경로에서 점점 멀어지고 있으므로 재라우팅이 필요하다. "경로를 다시 찾고 있어요. 잠시만요."를 안내하고 재라우팅 신호를 보낸다.

**CONVERGING → RETURNING (복귀 중)**:
경로로 돌아오고 있으므로 재라우팅하지 않는다. "다시 돌아오고 있어요. 잘 하고 있어요."로 안내하고 대기한다. 거리가 20m 이내로 돌아오면 NORMAL로 전환하여 기존 경로 안내를 재개한다.

**IRREGULAR → CONFIRMING (판단 보류)**:
장애물 회피 등으로 일시적으로 경로에서 벗어났다가 돌아오는 패턴일 수 있다. 추가 GPS 데이터를 받아 추세가 명확해질 때까지 모니터링을 계속한다.

## 8. 재라우팅

### 8.1 트리거 조건

상태가 **DEVIATED**로 전이되었을 때만 재라우팅을 수행한다. 즉, 다음 세 조건이 모두 충족되어야 한다:

1. 경로까지 최단 거리 > 20m
2. 이탈 의심 지속 시간 ≥ 5초
3. 최근 3개 거리값이 단조 증가 (멀어지는 추세)

### 8.2 재라우팅 절차

```
① 안내: "경로를 다시 찾고 있어요. 잠시만요."
② 현재 GPS를 새 출발지로 설정
③ 기존 목적지까지 Tmap 보행자 API에 경로 재요청
④ 새 경로로 길 안내 파이프라인(STEP 1~5) 재수행
   — DP 추출, POI 수집, 스코어링, 안내문 생성
⑤ 이전 경로와 겹치는 구간의 POI/파노라마 캐시 재활용
⑥ 안내: "새 경로를 찾았어요." → 새 경로 첫 안내 시작
```

### 8.3 캐시 재활용

이전 경로의 POI 검색 결과와 파노라마 Vision 데이터 중, 새 경로와 겹치는 구간의 데이터는 재사용한다. 예를 들어 이탈 지점 이후부터 목적지까지의 경로가 기존과 유사하면, 해당 구간의 POI·스코어링 결과를 그대로 쓴다. 이는 재라우팅 소요 시간을 줄이기 위한 설계이다.

### 8.4 이탈 감지 모듈 리셋

재라우팅이 완료되면 새 경로의 LineString으로 이탈 감지 모듈을 리셋한다. 모든 상태가 NORMAL로 초기화되고, 타이머·거리 기록·이전 GPS 등 내부 데이터가 전부 초기화된다. 이전 경로의 이력이 새 경로의 판정에 영향을 주지 않도록 하기 위함이다.

## 9. 한계점 및 설계 트레이드오프

### 9.1 GPS 음영 지역

고층 건물 밀집 지역, 지하도, 건물 내부에서는 GPS 신호가 약해져 정확도가 크게 떨어진다. 20m 오차가 일상적으로 발생하면 이탈 의심 상태에 빈번히 진입하게 된다. 현재 설계에서는 지속 시간 필터(3초)가 이를 어느 정도 완화하지만, GPS 음영이 길게 지속되는 환경에서는 한계가 있다.

### 9.2 좁은 골목 밀집 지역

경로와 평행한 골목이 20m 이내에 있으면, 실제로 옆 골목에 진입했는데도 경로까지 거리가 20m 이내로 측정되어 **정상으로 판정**될 수 있다. 거리 기반 판정만으로는 "경로 위에 있는 것"과 "경로에서 20m 이내의 다른 길에 있는 것"을 구분할 수 없다.

### 9.3 재라우팅 지연

이탈 확정부터 새 경로 안내 시작까지 Tmap API 재호출(네트워크) + 파이프라인 재수행(연산) 시간이 소요된다. 이 동안 사용자는 안내 없이 걷게 된다. "경로를 다시 찾고 있어요"라는 안내로 대기 상태임을 알리지만, 지연이 길어지면 사용자 경험이 저하된다.

### 9.4 설계 트레이드오프 요약

| 설계 선택 | 장점 | 단점 |
|---|---|---|
| 20m 임계값 | GPS 오차 흡수 + 실제 이탈 감지 | 20m 이내 평행 골목 미감지 |
| 3초 경고 지연 | GPS 일시 튐 필터링 | 실제 이탈 시 3초 늦은 안내 |
| 5초 + 추세 확인 | 불필요한 재라우팅 방지 | 이탈 확정까지 최소 5초 소요 |
| 3개 샘플 추세 | 빠른 판정 + 추세 신뢰 | 3개로는 노이즈 영향 가능 |
| 속도 필터 파괴적 폐기 | GPS 튐 완전 차단 | 정당한 빠른 이동도 무시 가능 |
| 경고 1회 발화 | 오디오 스팸 방지 | 사용자가 경고를 놓칠 수 있음 |
